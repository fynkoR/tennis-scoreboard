# 🎾 Tennis Scoreboard

Веб-приложение для ведения счёта теннисных матчей: создание матча, начисление очков в реальном времени, хранение истории завершённых матчей и поиск по имени игрока.

🌐 **Демо:** http://212.109.196.43

## Возможности

- Создание матча между двумя игроками (имена 3–20 символов, игроки не могут совпадать)
- Подсчёт счёта по правилам тенниса: очки (0, 15, 30, 40, AD) → геймы → сеты, тай-брейк
- Текущий счёт матча по уникальной ссылке (UUID)
- Список завершённых матчей с пагинацией
- Поиск завершённых матчей по имени игрока
- Единый формат ошибок (JSON) и валидация входных данных

## Чем проект особенный

Правила тенниса вынесены в отдельную **доменную модель** (`pet.project.models`), не зависящую от Spring, Hibernate и базы данных. Это обычные Java-классы, которые описывают предметную область:

- `Match` → `Set` → `Game` / `TieBreak` — иерархия, повторяющая устройство реального матча;
- интерфейс `Scorable` (`addPointTo`, `isFinished`) — общий контракт для гейма и тай-брейка, поэтому сет работает с ними одинаково;
- `Point` — перечисление очков (0, 15, 30, 40, AD) с переходом `next()`;
- правила (преимущество, возврат к равенству, победа с разницей в 2 очка, тай-брейк при 6:6, победа в матче при 2 выигранных сетах) реализованы внутри модели, а не в контроллерах или сервисах;
- недопустимые действия (очко в завершённом гейме, сете или матче) приводят к собственным исключениям.

Сервисы и контроллеры лишь вызывают модель и преобразуют результат в DTO, поэтому логику счёта можно проверять и менять независимо от остального приложения.

## Архитектура

- **Текущие матчи** хранятся в памяти (`MatchStorage`, `ConcurrentHashMap`) и идентифицируются по UUID.
- **Завершённые матчи** сохраняются в PostgreSQL (таблицы `Player` и `Matches`).
- Фронтенд — статические страницы, работающие с REST API через `fetch`/AJAX.

```
src/main
├── java/pet/project
│   ├── configs      # DispatcherServletInitializer, WebConfig (БД, Hibernate)
│   ├── controllers  # MatchController (REST API)
│   ├── services     # MatchService, PlayerService
│   ├── dao          # MatchDao, PlayerDao
│   ├── entities     # Player, Matches
│   ├── models       # Match, Set, Game, TieBreak — логика счёта
│   ├── enums        # Point, PlayerPosition
│   ├── dto          # запросы/ответы API
│   ├── exceptions   # исключения + GlobalExceptionHandler
│   ├── storage      # MatchStorage (матчи в памяти)
│   └── utils        # Validator
└── webapp
    ├── index.html, new-match.html, match-score.html, matches.html
    ├── css/, js/, images/
```

## REST API

| Метод | URL | Описание |
|---|---|---|
| `POST` | `/matches` | Создать матч. Тело: `{"firstPlayerName": "...", "secondPlayerName": "..."}`. Ответ `201`: `{"id": "<uuid>"}` |
| `GET` | `/matches/{uuid}` | Текущий счёт матча |
| `POST` | `/matches/{uuid}/point` | Начислить очко. Тело: `{"name": "<имя игрока>"}` |
| `GET` | `/matches?page=1&player_name=...` | Завершённые матчи (2 на страницу), фильтр по игроку необязателен |

Ошибки возвращаются в виде `{"message": "..."}` со статусами `400` (валидация), `404` (матч/игрок не найден), `409` (матч уже завершён), `500` (ошибка БД).

## Сборка

```bash
mvn clean package   # результат: target/tennis-scoreboard.war
mvn test            # тесты
```

Требуются JDK 17+, Maven и PostgreSQL. Параметры подключения к БД читаются из `hibernate.properties` (путь задан в `WebConfig`).

## Тесты

Логика счёта покрыта модульными тестами (JUnit Jupiter): всего 47 тестов, не требующих базы данных и сервера.

| Класс | Тестов | Что проверяется |
|---|---|---|
| `GameTest` | 15 | переходы очков, равенство и преимущество, победа с разницей в 2 очка, очко в завершённом гейме |
| `SetTest` | 12 | счёт по геймам, победа 6:0 и с разницей в 2 гейма, игра при 5:5, переход в тай-брейк при 6:6 |
| `MatchTest` | 11 | счёт по сетам, завершение матча при 2:0 и 2:1, победитель, очко в завершённом матче |
| `TieBreakTest` | 8 | победа при 7 очках и разнице в 2, отсутствие победы при 7:6, очко в завершённом тай-брейке |
| `PointTest` | 1 | исключение при попытке взять очко после преимущества |

Запуск: `mvn test`.
